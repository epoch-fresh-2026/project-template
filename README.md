# 流程单

这是一份给新手看的开发顺序。改代码不是直接改，而是按五步走：先把要做的事写下来，从主线拉出一条自己的线，在自己电脑上检查，把改动交上去请人看，别人同意后再并进主线。

先认识几个会反复出现的词：

- **Issue**：一件先写下来的事。可以是要修的问题，也可以是要做的功能。改代码之前先开一条。
- **main**：仓库里的正式主线。已经收进来的代码都在这里。
- **分支**：从主线拉出来的一条临时线。改动先写在这条线上，不直接改主线。
- **PR**：Pull Request 的缩写，就是一份申请。你把分支上的改动交上去，请别人看。别人同意，才能并进主线。
- **CI**：提交之后由 GitHub 自动跑的检查。和你在自己电脑上跑的是同一组命令。

这是个纯前端项目，文件按 Next.js 默认方式放。一个人维护自己的仓库时，分支和 PR 都留在这个仓库里，不用 fork。fork 是把别人的仓库复制到自己名下，只有几个人一起做、而你又不能直接改主仓库时才需要。

## 在自己电脑上打开

需要 Node.js 20.9 或更高版本。

```bash
npm ci
npm run dev
```

打开 http://localhost:3000 。

## 交上去之前要跑的检查

按这个顺序跑。CI 会再用同一组命令跑一遍：

```bash
npm run lint
npm run typecheck
npm run test
npm run build
```

`lint` 看代码有没有明显问题，`typecheck` 看类型对不对，`test` 跑测试，`build` 看能不能成功打包。

## 线上能打开的页面

GitHub Pages 是 GitHub 提供的免费静态网页。这个仓库每次并进 main 之后，会自动把页面发到：

https://epoch-fresh-2026.github.io/project-template/

地址里的 `project-template` 是仓库名。页面挂在这个名字下面，不是网站根目录。这只是方便打开来看流程单，和后面说的 Release 不是一回事。Release 是打版本标签，告诉别人这一版代码可以拿去用。

## 准备改这个仓库

先看 [CONTRIBUTING.md](CONTRIBUTING.md)，里面按顺序写了每一步怎么做。仓库里还有新建 Issue、新建 PR 时会自动出现的模板，打开就能看到一份写好的例子。
